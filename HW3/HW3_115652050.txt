延伸問題
1:讓沒有主元選擇的消去法「翻車」
A:1. 讓沒有主元選擇的消去法「翻車」

要刻意讓未加入部分主元選擇的消去法算出極度離譜的解，最經典的設計是將第一步的對角線主元設定為一個極小但不為零的浮點數ε（例如 1e-16）。
我們可以設計以下 2 x 2 線性系統：
[ ε   1 ] [ x1 ] = [ 1 ]
[ 1   1 ] [ x2 ]   [ 2 ]

- 捨入誤差被放大的過程：
  在消去第二列時，程式會計算出一個極巨大的乘數：m = 1 / ε = 10^16。
  接著更新第二列的元素：a_22 = 1 - (10^16 * 1)。
  在標準雙精度浮點數（double）的底層儲存機制中，當一個普通數字（1）減去一個極巨大的數字（10^16）時，會發生「大數吃小數」的嚴重精度遺失，有效位數會被完全截斷，導致電腦算出的 a_22 直接變成 -10^16。同理，右側的 b2 = 2 - (10^16 * 1) 也會變成 -10^16。

- 誤差結果：
  回代求解時，x2 = (-10^16) / (-10^16) = 1。
  接著算 x1 = (1 - x2) / ε = (1 - 1) / ε = 0。
  這個系統真實的精確解大約是 x1 ≈ 1, x2 ≈ 1。
  你的程式卻會算出 x = (0, 1)^T，其中 x1 產生了 100% 的巨大誤差。這個現象完美展示了當對角線主元極小時，會製造出巨大的乘數，進而在後續的運算中將浮點數的捨入誤差無限放大，直接摧毀原始數據的精確度。


2. 為什麼不該直接求 A^-1？

在數值線性代數中，透過計算逆矩陣來解 x = A^-1 * b 是極度不建議的實務做法，因為這會在運算次數與精度兩個層面上造成嚴重的效能劣化。

- 運算次數：
  * 直接消去 ＋ 回代：將矩陣 A 化為上三角矩陣（相當於 LU 分解）需要約 (1/3)n^3 次浮點運算，隨後對單一向量 b 進行前代與回代的運算量僅為 O(n^2)。整體時間複雜度的常數項就是 (1/3)n^3。
  * 求逆矩陣 A^-1：若透過高斯消去法求解 A^-1，等於是將右側的 b 擴充為一個 n*n 的單位矩陣，也就是要對單位矩陣的每一行分別求解n 次。這會將消去過程的乘加運算次數暴增至精確的 n^3 次。取得逆矩陣後，還必須額外花費 n^2 次運算去執行 A^-1 * b。
  * 結論：理論上，求解逆矩陣的運算成本確實精準地落在 LU 分解（或直接消去法）的三倍。如果在程式中實際測量這兩種方法的 CPU 執行時間，實測結果的倍率會非常吻合這個 1 : 3 的理論值。

- 精度上的差異：
  直接解 A * x = b 時，誤差只會在消去過程與單一向量 b 的交互運算中產生。
  但如果先求 A^-1，矩陣內的所有 n*n 個元素都必須歷經漫長的 O(n^3) 次乘加運算，這會使得捨入誤差在矩陣內部進行大量的疊加與傳播。
  最後在執行 A^-1*b 時，又要再進行一次矩陣向量乘法，等於是把已經含有誤差的逆矩陣再次與b相乘，這會導致最終解x 的誤差範圍顯著大於「直接消去＋回代」的結果。
