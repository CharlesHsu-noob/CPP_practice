程式架構主要分為以下幾個模組：

6.霍納法則 (honorWayPolynomial 與 horner)：由最高次項（陣列末端）往常數項（陣列開頭）迭代，每次反覆執行ans=ans*x+coff[i]。

例如 horner 函式被設計為 Template，只要傳入的型別（如 double 或 complex<double>）支援加法與乘法運算子重載，就能直接套用此演算法。

這是為了防止現代編譯器過度優化而省略計算過程，確保傳統算法與霍納法則都會被實際執行，便於日後進行精確的效能測量。

延伸問題
    Q1:Horner法除了省下乘法次數，是否也連帶減少了浮點捨入誤差的累積機會？為什麼「越少次浮點運算」通常也意味著「誤差越小」？
        是的，Horner 法確實能減少浮點捨入誤差的累積機會。
        在電腦科學中，浮點數的運算（例如加法和乘法）並不完美，每次運算都可能因為有效位數的限制而產生微小的捨入誤差。
        傳統的求值法需要進行O(N^2)次運算，這意味著誤差有更多的機會在每次運算中被捨入並累積起來。
        相對地，Horner 法將運算次數降低到了O(N)，由於進行的運算次數變少了，自然也減少了捨入誤差發生的次數，因此總體的累積誤差通常會比較小。
    Q2:如果x的絕對值很大（例如 |x|>>1），傳統求值法中 std::pow(x, n) 這一項是否可能先發生溢位（overflow），而 Horner 法卻不會？試著設計一組數字驗證看看。
        是的，有可能發生這種情況。
        傳統求值法會先獨立計算x^n，如果x和n都很大，這個獨立計算的結果可能會直接超出浮點數所能表示的最大範圍（例如 double 的上限），導致溢位產生無限大。
        而 Horner 法是逐步地將前一項的結果乘以x再加上係數，如果多項式的係數非常小，這種交替相乘和相加的方式有機會將數值拉回安全範圍內，從而避免溢位。
        驗證設計：假設有一個多項式 P(x) = 10^-300 * x^2，我們令x=10^200。
        傳統求值法：程式會先計算 std::pow(10^{200}, 2)，也就是 10^{400}。
        由於 10^400 超過了 C++ 中 double 型別的上限（約 1.79e308），這一步就會發生溢位，回傳 inf。
        接下來無論怎麼乘以極小的係數10^-300，結果都還是 inf。
        Horner 法：運算過程為 (10^{-300} * 10^{200})+0 =10^{-100}，接著再進行下一步 (10^{-100} * 10^{200}) + 0 = 10^{100}。
        結果會正確地落在可表示的範圍內，不會發生溢位。
    
    Q3:如果係數a_k全部是實數，但輸入的 x是複數，函式是否還能直接運作？需要對範本或型別做什麼調整？
    答：無法直接運作。
        如果在原本的設計中只使用單一範本參數（例如 template <typename T>），
        當您傳入實數係數陣列 vector<double> 與複數變數 complex<double> x 時，編譯器在進行型別推導時會產生衝突
        （無法決定 T 到底該是 double 還是 complex<double>），進而導致編譯錯誤。   
        調整方式：需要將範本擴充為「兩個獨立的型別參數」，讓係數與 x可以是不同的型別，並且將回傳型別設定為涵蓋範圍較大的型別（即複數型別）。
        程式碼調整範例如下：
        template <typename CoeffType, typename XType>
        XType horner(const std::vector<CoeffType>& a, XType x) {
            XType result = a.back();
            for (int k = (int)a.size() - 2; k >= 0; --k) {
                // C++ 的 complex 已經支援與純量(double)直接相加，
                // 但確保型別安全，運算時會自動將實數係數隱含轉換為複數
                result = result * x + XType(a[k]); 
            }
            return result;
        }

    Q4:「複解析函數沒有反例」與「Horner 法更省時」的效率議題，是同一個層次的問題嗎？兩者分別回答的是什麼問題？
    答：完全不是同一個層次的問題。
    這兩者分別代表了「純數學理論」與「計算機應用/演算法」兩個截然不同的領域。   
    「Horner 法更省時」回答的是「演算法效能與計算複雜度」的問題：它屬於計算機科學的層次。
    探討的是在現實世界的電腦硬體架構下，如何透過改變數學運算的先後順序，把執行的指令數量從 O(N^2)降低到 O(N)，藉此節省 CPU 資源並減少浮點數捨入誤差的累積。
    「複解析函數沒有反例」回答的是「純數學結構與分析」的問題：它屬於數學與複變函數論的層次。
    探討的是在抽象的複數平面上，函數具備「可微性」與「解析性（能展開為冪級數）」之間的深刻關聯。這是一條描述空間本質與函數幾何特性的定理，
    完全不涉及現實中電腦是怎麼「一步一步算出數字」的過程。
